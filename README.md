# GuaGrid v1 · 卦阵

卦阵在本机调度八个独立的 Codex 会话。乾、坤、震、巽、坎、离、艮、兑各有自己的角色、Skill 和 MCP 配置，可以并行做事，也能查到彼此的进度和成果。

## 启动

准备 Node.js 22 或更新版本、Git，以及已登录的 Codex CLI。启动时把 `--workspace` 指向要工作的 Git 仓库。卦阵从它已经提交的 `HEAD` 创建独立工作目录。

```sh
codex login status
npm start -- --workspace /path/to/your/repo
```

打开 [本地工作台](http://127.0.0.1:8788/)。默认用「八卦协作」完成一项任务。八席用同一 Git 基线在独立工作区同时开工，全程使用 GPT-6 Luna。乾定计划与结构，坤管资源和基线，震写代码，巽查资料与索引，坎管环境与运维，离写规格和文档，艮独立验收，兑梳理需求。也可以单独运行 Step 1、自动分派或指定一卦。

每项任务可以建一个会话。左栏用来切换会话；顶部可选某一卦的对话，沿用它在这个会话里的 Codex 上下文。时间线中可展开命令、文件和通气记录，也可以按原顺序回放并跳到关键节点。右侧的八卦协作图显示各卦状态和通气方向，点卦名切换对话，点通气卡片展开原文。

## 卦的配置

`profiles` 目录下每一卦都有一份 `AGENTS.md`、`SKILL.md` 和 `mcp.json`。卦阵把角色说明和预置 Skill 传给独立会话，Codex 也会加载任务工作目录的项目指令。

每卦都启用本机 `guagrid` MCP 的 `get_grid_status`。传入 `agent` 可以查单个卦，省略时返回同组职责和状态。八卦协作可用 `get_handoff` 查交付，`publish_handoff` 发布本卦带版本的成果。乾可在 `structure` 交接登记本轮文件归属。`explore_forks` 从同一基线并行试两条路线，每条路线有独立 Codex fork 工作区和共同检查条件。

八卦协作中，`tongqi` 可以找同组任意其他卦，发送后立即返回请求编号。应方从自己的会话只读 fork 预分析，回「应」时给出是否接受。接受的通气会把原文和预分析一起写回应方主会话。信息流会显示「感」「应」和写回结果。Step 1 仍可在调用内收到回复。

各卦的 `mcp.json` 中，`tools` 是内置工具清单，`servers` 可以提供额外的 Codex MCP 服务器配置。巽和离分别附了 Context7 和 Playwright 的启用示例。

## 工作结果

当前工作以 `B0` 标记初始 Git 提交，集成分支名为 `guagrid/<协作ID>`。代码、运维和文档分别由震、坎、离维护，卦阵按实际 Git diff 校验范围，再以坤的集成职责逐项合入。艮复跑指定提交并交回证据，验证通过后才记录已验收基线。发现问题时可指定主责卦返工，记录保留在工作台。

`POST /api/sessions/<原会话ID>/rerun` 使用原话和原 Git 基线另开一轮。请求可带 `variants` 和 `checks` 让震并行比较两条实现路线。回放的基线、派发、fork、合入和验收都使用实际事件。

验收环境遇阻后，可用 `POST /api/sessions/<会话ID>/recheck` 传入 `commit` 和该提交的实际 `evidence`，由艮复验同一提交。旧结论和补充证据都保留在账本。

服务绑定本机回环地址。任务和会话写入 `~/.guagrid/<工作仓库标识>/state.json`。卦阵逐条写入 `trace/<会话ID>.jsonl`，交接版本、文件候选与当前清单保存在 `work/<协作ID>/`。旧会话可用保留的工作台事件和本机 Codex 日志回放。重启时，在途任务会标记为中断，保留已有 worktree、交接和候选。可用 `--state-dir` 指定存储位置，`--port` 改端口，`--codex` 指定 CLI 路径。

```sh
npm test
```

测试用临时 Git 仓库和 Codex 接口替身覆盖并行派发、文件归属、候选重叠、按提交验收与同基线重跑。
